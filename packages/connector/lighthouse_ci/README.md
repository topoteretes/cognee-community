# Lighthouse CI Report Connector for Cognee

The official `lighthouse_ci` data-source connector for [Cognee](https://github.com/topoteretes/cognee), syncing web performance, accessibility (a11y), SEO, and Core Web Vitals audit reports directly into AI agent memory and graph/vector stores.

---

## Overview

Lighthouse CI generates critical performance, accessibility, SEO, and best-practice audit results across development and CI/CD pipelines.

This connector ingests Lighthouse Result (LHR) JSON files generated by `lhci collect` or Lighthouse CLI into structured, searchable markdown documents for Cognee's document ingestion pipeline (`cognify()`). AI coding agents can retrieve previous audit findings, trace recurring regressions, and compare metrics across recorded builds.

### Key Capabilities

- **Local & CI File Ingestion**: Ingests directly from a directory (e.g. `.lighthouseci/`) or explicit file list without requiring external API credentials.
- **Metric Extraction**: Normalizes category scores (0-100) and Core Web Vitals (LCP, FCP, TBT, CLS, Speed Index).
- **Actionable Diagnostic Findings**: Isolates failing audits, opportunities, and byte/time savings while stripping bulky raw traces and screenshots.
- **Privacy & Security**: Automatically sanitizes sensitive URL query parameters (e.g. `token`, `key`, `password`, `session`).
- **Build Provenance**: Preserves optional `build_id` and `commit_sha` metadata to track regressions across releases.
- **Document-Mode Routing**: Declares `DOCUMENT_SOURCE_ATTR = "lighthouse_ci"` so audit findings flow through Cognee's entity extraction and relationship graph.

## Quickstart

### 1. Ingest Lighthouse CI Reports into Cognee

```python
import asyncio
import cognee
from cognee_community_connector_lighthouse_ci import lighthouse_ci_source


async def main():
    # 1. Point to your local .lighthouseci directory generated by `lhci collect`
    source = lighthouse_ci_source(
        reports_dir="./.lighthouseci",
        build_id="build-1042",
        commit_sha="a5b7c8d",
    )

    # 2. Ingest into Cognee staging
    await cognee.add(source)

    # 3. Cognify: extract entities, relationships, and vector embeddings
    await cognee.cognify()

    # 4. Search audit memory
    results = await cognee.search(
        "Which accessibility issues and color contrast failures were detected?"
    )
    for res in results:
        print(res)


if __name__ == "__main__":
    asyncio.run(main())
```

### 2. Ingest Specific Report Files

source = lighthouse_ci_source(

## Document Schema & Metadata

Each report is formatted as a structured Markdown document and tagged with:

| Field | Type | Description |
|---|---|---|
| `id` | `str` | Deterministic report identifier |
| `url` | `str` | Sanitized audited URL |
| `title` | `str` | Standardized header `[Lighthouse CI] <URL> (<Timestamp>)` |
| `fetch_time` | `str` | ISO audit execution timestamp |
| `lighthouse_version` | `str` | Engine version used for audit |
| `performance_score` | `int` | Performance category score (0-100) |
| `accessibility_score` | `int` | Accessibility category score (0-100) |
| `best_practices_score` | `int` | Best Practices category score (0-100) |
| `seo_score` | `int` | SEO category score (0-100) |
| `build_id` | `str` | Optional CI build ID |
| `commit_sha` | `str` | Optional git commit hash |
| `content` | `str` | Structured Markdown body with Core Web Vitals & diagnostic findings |
